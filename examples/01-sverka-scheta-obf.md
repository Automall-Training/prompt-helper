# Пример: задача большая → запуск `one-big-feature`

## Вход

«Каждую неделю бухгалтерия сверяет счета поставщиков с нашими заказами вручную. Хочу, чтобы ИИ делал это сам».

## Ответ скилла (сокращённо)

«Роль: задача. Красной зоны нет, если примеры обезличены.
Путь: one-big-feature — процесс повторяется, а готового скилла нет: `buhgalter` сверяет расчёты по акту поставщика, но не сверяет построчно счёт с нашим заказом.
Вопрос 1. Где взять примеры? 1) 3–5 обезличенных пар „счёт + заказ“ в папке input/ (рекомендую) 2) Опишу словами, примеры позже»

→ … вопросы по одному: формат счетов (PDF, Excel), какие расхождения важны (цена, количество, артикул), порог, кто решает спорное, что только после «да» →

Сводка «Я понял так… Путь: one-big-feature (Codex, отдельная папка)… Верно?» → «да» → запуск по шаблону:

```text
$one-big-feature Собери скилл для Codex для [ваша компания] по процессу: сверка счёта поставщика с нашим заказом.
Цель: скилл сверяет каждую строку счёта с заказом. Готово = скилл прошёл все 5 примеров из input/, нашёл заложенные расхождения и показал «пришло = сошлось + к человеку».
Входы: input/schet-1..5.pdf и input/zakaz-1..5.xlsx (обезличенные, копии).
Результат: skill/sverka-schyota/SKILL.md (name, description), references/pravila-sverki.md, examples/.
Правила процесса: расхождение по цене больше 1 % или по количеству — в «К человеку»; артикул сверяем по справочнику.
…
```

## Почему так

- Задача повторяется каждую неделю: разовый промпт пришлось бы каждый раз писать заново, а скилл зовут одним словом.
- Нужны примеры, правила и проверка на них: это несколько частей, их удобно делать и проверять по фазам.
