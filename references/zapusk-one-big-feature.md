# Шаблон запуска `one-big-feature`

Выдаётся вместо обычного промпта, когда в шаге 1 выбран путь «one-big-feature». Перед шаблоном — одна строка: «Это большая задача. Откройте **Codex** (или Claude Code) в **отдельной папке**, одна задача — одна папка — один чат, и вставьте запуск целиком. Если папка ещё не git-папка — сначала: „Сделай в этой папке git init и первый коммит. Больше ничего не делай“».

```text
$one-big-feature <что собрать одной фразой: скилл / небольшая программа / автоматизация> для [ваша компания] по процессу: <процесс словами>.

Цель: <что получить>. Готово = <проверяемый признак: например, скилл прошёл все примеры из input/ и отчёт показывает «пришло = взяли + отложили»>.
Входы: <обезличенные примеры — точные пути; скопируй их в input/, оригиналы не меняй>.
Результат: <для скилла — skill/<имя>/SKILL.md по формату Agent Skills (name, description), references/, examples/; для программы — папка и как запустить>.
Правила процесса: <пороги, справочники, кто подтверждает спорное; что считать ошибкой>.
Спорное — на лист или в раздел «К человеку», сам не решай. Пусто — не ноль.
Персональные данные не используем: только обезличенные примеры («Клиент А», «Поставщик 1»).
Деньги: <что платное>; лимит — <число/сумма>. Без ключей API, если без них можно.
Только после моего «да»: <отправка, публикация, изменения в рабочих системах (1С, CRM, реклама)>.

Задавай вопросы по одному. После ответов работай сам до конца по всем фазам, без подтверждений между фазами.
Критерии проверки:
- <3–5 признаков, которые проверяются глазами за минуту>
В конце — финальный отчёт: что сделано, где лежит, как установить и запустить, что проверить человеку.
```

Под запуском: «**Что подставить:** <поля в угловых скобках>» и «**Сколько ждать:** обычно час-два; пока работает — в другом чате можно делать следующую задачу».
